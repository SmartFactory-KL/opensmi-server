# Migration

This guide should help users to upgrade to the newest version.

[[_TOC_]]

## v4 -> v5 Server

- Everywhere (Machine, Component, Skill, etc.):
    - `self.server`/`self._server` removed. Now, there is a global PyUaAdapter singleton via `get_server()`. To access
      the asyncua server, use `server.ua_server`
    - All functions which required `server` and/or `config` parameter no longer do so.
  - `self.config` removed. To access the server config, use `server.config`.
  - Machine specific `ns_idx` removed, it was and is **always** 1. (First namespace created other than OPC UA Foundation
    defined NS0)
  - `__init__()`:
    - parameters `server`, `ns_idx` and `config` were removed. If required, get via server singleton.
    - parameter `parent`  was removed. now a property settable before initialization (usually done automatically by the
      parent)
    - every parameter keyword-only
  - Async properties were removed. Use corresponding `read_*()` methods instead!
- ua_types.py replaced with [ua_node_ids.py](../src/open_smi/server/ua_node_ids.py), now autogenerated →
  organization &
  naming changed.
  - SF Machine & Skill node set is always imported, import your required node sets before first use.
- introduced life cycle, added many checks to prevent wrong API use.
  - `init()` methods no final and take no parameters. all config is done via `__init__()`. To implement initialization
    logic, override `_init()`. Same for `shutdown()` -> `_shutdown()`
- `add_*()` no longer accept types, instances only! Reason: Less complicated, better IDE/type checker support, etc.
  - removed specific `add_*()` like `add_port()`, because instantiating components is now much simpler :)
  ```python
  await self.add_component(DummyPort(port_number=1, rfid_tag_own=232, rfid_tag_neighbor=80, couple_delay=0.5))
  ```
- OPC UA based Logging:
  - `_log_*` methods are named `ua_log_*`, i.e. `_log_error` methods are now `ua_log_error`.
  - Components have to either need to inherit the `NotificationMixin` or `NotificationForwardMixin`
    (see [notification_mixins.py](../src/open_smi_server/mixins/notification_mixins.py) for details)
  - Modules automatically inherit `NotificationMixin`
- AccessControl now in server, Lock in machines and optionally in components.
  - `server.access_control`
  - `self.lock`
- removed everything deprecated in v4. Most critical:
    - `_condition_skill_ready` for skills, use `_condition_start_allowed()` instead.
    - Config-based module initialization removed, instead use the following for example:

```python
import asyncio

from open_smi_server import get_server
from tests.dummy_module.config import TestConfig
from tests.dummy_module.dummy_machine import DummyMachine


async def main() -> None:
    async with get_server() as server:
        await server.configure(TestConfig())
        await server.init()
        await server.add_machine(DummyMachine())
        await server.start(blocking=True)


if __name__ == "__main__":
    asyncio.run(main())
```
## v3 -> v4 Server

### Component Identification

- Component Identification Initialization - Introduced the ```_init_component_identification``` method that must be 
implemented for each subtype of ```BaseComponent```:
```python
async def _init_component_identification(self) -> None:
    await self._init_identification()
```
- Change Description: This method was added to support the introduction of ```_id``` in the constructor 
and ensure proper component identification initialization.

### Machine Identification

- Machine Identification Initialization - Introduced the ```_init_machine_identification``` method that must be
  implemented for each subtype of ```BaseMachine```:
```python
async def _init_machine_identification(self) -> None:
    await self._init_identification()
```
- Change Description: This method was added to support the introduction of ```_id``` in the constructor and ensure proper machine identification initialization.


### Constructor of Components

- Constructor Update - Updated the constructor in `Components`:
  ```python
  # Previous version (v3)
  def __init__(self, server, parent, ns_idx, name: str, config, _id: int):
      super().__init__(server, parent, ns_idx, name, config)
      self.logger.info("Init Ros2Component: {name}")

  # New version (v4)
  def __init__(self, server, parent, ns_idx, _id: str, name: str, config, spatial_object=None):
      super().__init__(server, parent, ns_idx, _id, name, config, spatial_object)
      self.logger.info("Init Ros2Component: {name}")  
  
- Change Description: Added the parameter ```_id``` to the constructor.
- Change Description: New Instantiation Method:
  - The component is now instantiated with ```_id``` as shown:
```python
await self.add_component(
    _id=str(uuid.uuid4()), 
    name="Specific-Component", 
    component_type=SpecificComponent
)
```

### Constructor of Module

- Module Constructor Update - The constructor for the module has been updated in `v4` to include an `_id` parameter, similar to the changes made for components.

```python
# Previous version (v3)
def __init__(self, server, ns_idx, config):
    super().__init__(server, ns_idx, "Module", config)
    ...


# New version (v4)
def __init__(self, server, ns_idx, config):
    super().__init__(server, ns_idx, str(uuid.uuid4()), "Module", config)
    ...
```

- Change Description: The constructor now generates and passes a unique ```_id``` using ```str(uuid.uuid4())```.
- Change Description: The ```uuid``` module must be imported to support this change.


### Components 

- Component Initialization Update - In `v4`, the method for initializing components has been updated,
  replacing `_init_assets` with `_init_components`.

  ```python
  # Previous version (v3)
  async def _init_assets(self) -> None:
      await super()._init_assets()

      await self.add_component("DummyComponent_Test", DummyComponent, _id=42)
      await self.add_component("RAV-Platform", Ros2Component, _id=15)

  # New version (v4)
  async def _init_components(self) -> None:
      await super()._init_components()
  
      await self.add_component(_id=str(uuid.uuid4()), name="ROS2-Component", component_type=Ros2Component)

- Change Description: Replaced `_init_assets` with `_init_components` for improved clarity and consistency.
- Components are now initialized with a dynamically generated unique `_id` using `str(uuid.uuid4())`, replacing hardcoded IDs.
- The `uuid` module must be imported to generate unique IDs.

### Skills

#### Constructor

Changed the constructor for all Skills:

```python
# Previous version (v3)
def __init__(self, name: str, module, delay=1, dependencies: list = None, ros2_action: str = ""):
    super().__init__(name, module)

# New version (v4)
def __init__(self, name: str, machinery_item, delay=1, dependencies: list = None, ros2_action: str = ""):
    super().__init__(name, machinery_item)
```

- Change Description: The parameter ```module``` has been replaced with ```machinery_item```.

#### Logic definition

Previously (v3 and before), logic in skills was defined by overriding ```_before_XXX``` and ```_after_XXX``` methods.
For example ```_before_reset``` could be used to define logic that should reset the skill. The ```_after_start``` method
was basically always the same copy&paste code from the dummy example, which created a new task to work around the OPC UA
time out. Logic that was defining how the skill should behave during RUNNING state was then done in ```_handle_running```.

In the new version, the ```_before_XXX``` and ```_after_XXX``` methods no longer exist. Instead, there are now the 
following ```_handle_XXX``` methods instead. Additionally, there are now new conditions that can be optionally used
to prevent the transitions for reset(), start() and suspend(). 

```python
async def _handle_resetting(self):
    """Is called to handle user-specific logic during RESETTING state. After this function is done,
    the skill will automatically advance to the READY state."""


async def _handle_starting(self):
    """Is called to handle user-specific logic during the STARTING state. After this function is done,
    the skill will automatically advance to the RUNNING state."""


async def _handle_running(self):
    """Is called to handle user-specific logic during the RUNNING state. After this function is done,
    the skill will automatically advance to the COMPLETED state if it is finite, else HALTING state."""


async def _handle_halting(self):
    """Is called to handle user-specific logic during the HALTING state. After this function is done,
    the skill will automatically advance to the HALTED state."""


async def _handle_suspending(self):
    """Is called to handle user-specific logic during the SUSPENDING state. After this function is done,
    the skill will automatically advance to the SUSPENDED state."""


async def _handle_completing(self):
    """Is called to handle user-specific logic during the COMPLETING state. After this function is done,
    the skill will automatically advance to the COMPLETED state."""


async def _condition_start_allowed(self, _user: User) -> bool:
    """Implement custom conditions checked before starting the skill."""


async def _condition_reset_allowed(self, _user: User) -> bool:
    """Implement custom conditions checked before resetting the skill."""


async def _condition_suspend_allowed(self, _user: User) -> bool:
    """Implement custom conditions checked before suspending the skill."""
```

To migrate, you should move the code from the old ```_before_XXX``` and ```_after_XXX``` methods to the 
respective ```_handle_XXX``` methods. For continuous skills, you need to split the old ```_handle_running``` into 
```_handle_starting``` and ```_handle_running```. The dummy skills have been updated to serve as examples. 

> [!important]
> Your code should no longer need to trigger any state machine transitions like 
> ```await self.machine.done_internal()```! You need to remove them completely!

#### StartupSkill

> [!note]
> There is now a [BaseStartupSkill](../src/open_smi_server/base_startup_skill.py) available.

A Startup skill is required for the module and optional for components. The startup skill for components is only 
required, if that component requires special startup sequences etc. Else, the only all sub-components and all skills 
are reset.

### Monitoring and Diagnostics

- Monitoring/Diagnostics Function Update -
  In `v4`, the `_init_diagnostics` method has been replaced with `_init_monitoring`, resulting in changes to inheritance and task management.  

```python
  # Previous version (v3)
  async def _init_diagnostics(self) -> None:
      await super()._init_diagnostics()
      ...
  
  async def _init_assets(self) -> None:
      await super()._init_assets()
      
      self._monitoring_update_task = asyncio.ensure_future(self._update_monitoring())
      if isinstance(self._parent, BaseModule):  # prevent infinite
          pass

  # New version (v4)
  async def _init_monitoring(self):
      await super()._init_monitoring()
      self._monitoring_update_task = asyncio.ensure_future(self._update_monitoring())
```

- Change Description: ```_init_diagnostics``` has been replaced with ```_init_monitoring```.
- Change Description: The task for the ```_update_monitoring``` function is no longer created in ```_init_assets```.
Instead, it is now directly initialized in ```_init_monitoring```.

### Config
- Initial State Configuration Update -  
  In `v4`, the initial state values for modules, skills, and gates have been updated to reflect new state definitions.

```python
  # Previous version (v3)
  MODULE_INITIAL_STATE = "Ready"
  SKILLS_INITIAL_STATE = "Ready"
  GATE_INITIAL_STATE = "Ready"

  # New version (v4)
  MODULE_INITIAL_STATE = MachineryItemStates.NotExecuting
  SKILLS_INITIAL_STATE = SkillStates.Ready
  GATE_INITIAL_STATE = SkillStates.Ready
```

- Change Description: The value for ```MODULE_INITIAL_STATE``` has been changed to ```MachineryItemStates.NotExecuting```
- Change Description: The values for ```SKILLS_INITIAL_STATE``` and ```GATE_INITIAL_STATE```
have been updated to ```SkillStates.Ready```.

### Resources

Resources have been completely redone in `v4`. There are already ready-to-use Resources inheriting from `BaseResource`
in [resources](../src/pyuaadapter_sfkl/resources), for example the old Nubstone, Battery, Carrier and Truck resources.

```python
# Previous version (v3)
await self._add_resource("UsbPenDrive_2x4_Red", "Red", "UsbPenDrive", "2x4", 69)

# New version (v4)
await self.add_resource(UsbPenDrive_2x4_Red, amount=69)
```

Please feel free to contact a maintainer to add the missing resources for you.
